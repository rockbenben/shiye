# /expand - 拆解收件箱

把 `data/inbox/` 里还没处理的条目拆成任务，写进 `data/outbox-<unique>.json`
**这一类文件**（文件名自己挑一个唯一的，比如带上时间戳），不碰 `data/tasks/`、也不碰
`data/inbox/`——这两个目录永远只由服务写，理由见 `AGENTS.md` 开头那段：拆解一次要
一分半钟，这中间用户在网页上点掉、删掉的东西不该被你收工时的整体回写盖掉。

字段规则（`status` 取值、`due` 和 `reminders` 的区别、时间格式、`reminders` 里
`firedAt` 必须是 `null`、`habit` 跟 `repeat` 怎么搭配……）都在 `AGENTS.md`「拆解要
做的事」一节，这里不重复。

## Step 1: 找出要处理的条目

读 `data/inbox/` 目录，挑出 `processed: false` 的条目。一条都没有就如实说「没有需要拆的」，
不要凭空造一条 outbox 出来。

## Step 2: 逐条拆解

每条按 `AGENTS.md` 的规则产出一个或多个任务对象，判断成「这不是任务」也算处理完了——
那种情况这一条对应的 `tasks` 给空数组。

## Step 3: 一次性写 outbox-<unique>.json

把所有条目组装成一个数组，一次写完整个文件：

```json
[
  { "inboxId": "…", "tasks": [ { 完整任务对象 } ] }
]
```

**不要写了第一条就先落盘、拆完下一条再追加。** 服务的文件监听器会在写入停顿约 200
毫秒后去读这个文件——分多次写虽然不会把半截内容错误合并（校验不过就整批拒收），
但会让用户看到一条没道理的失败提示，然后你后面几次写又会把它覆盖掉，全程用户只看见
一堆噪音。

**文件名自己挑一个唯一的**（时间戳或者随机字符都行），别用固定名字：这个文件夹里
随时可能有另一个你（网页「立即拆解」触发的那个进程）在同时写，撞了同一个文件名会
互相覆盖。**原子写**：先写 `outbox-<unique>.json.tmp`，写完再改名成
`outbox-<unique>.json`——直接写最终文件名的话，监听器有极小概率读到你写到一半的
半截 JSON。

## Step 4: 汇报

写完 outbox 文件就完事了——不用等，也不用自己去改 `data/inbox/` 或 `data/tasks/`，
服务会在几百毫秒内把它合并进看板并删掉这个文件（前提是服务在跑，见 `AGENTS.md`）。
跟用户说清楚：拆了几条、每条拆成了什么、有没有判断成「不是任务」的。

## 规则

1. **这次会话唯一要写的文件就是 `data/outbox-<unique>.json`（文件名自己起）。**
   别的路径不管多顺手都不要碰。
2. **校验失败这次调用未必看得到。** 合并失败时 SSE 会推一条红色横幅，但那是给盯着
   网页的人看的，你这次调用可能已经退出了。字段按 `AGENTS.md` 写对，比事后排查省事。
3. 由服务触发时——网页点「立即拆解」经 `POST /api/expand`，或者收件箱安静下来后
   服务按设置里的延迟自动排期触发（见 `2026-08-11-auto-expand-design.md`）——
   传给你的提示词都只会说「读 AGENTS.md 和 workflows/expand.md，处理收件箱里还没
   处理的条目」，两种触发方式共用同一句话。本文件就是那句话指向的正本。

   **唯一的例外**：用户在设置里把「怎么叫 AI」换成了「调接口」时，你不是一个能读写
   文件的进程，而是一次普通的对话调用——那种情况下服务会把本文件和 `AGENTS.md` 的
   原文直接贴给你，末尾另加一段明确写着「你这次没有文件系统」的说明，让你把 JSON
   数组直接回出来、由服务代写。**看得到那段说明就照它办，看不到就照本文件办**，
   两者不会同时出现，你也不需要自己判断现在是哪一种。
